# 변경 사항과 호환성 안내

이 문서는 현재 작업본의 변경 사항을 설명합니다. 패키지 게시 여부와는 별개입니다.

## 수정 사항

- `meta-buffer-pack` 2.1.4를 반영했습니다.
- 수신 패킷의 최소 길이·유형·선언 길이를 검증합니다.
- `ENC_488` 수신은 인증 상태를 확인합니다.
- `ENC_E2E`는 암호화된 라우팅 헤더와 뒤의 암호화 본문을 구분합니다.
- E2E 처리에서 예외가 발생해도 원래 키와 계산 상태를 복원합니다.
- 빈 본문을 지원하고, 키 미설정·빈 키·잘못된 raw key 길이를 거부합니다.
- TypeScript 기본 export와 정적 속성의 선언을 실제 API에 맞췄습니다.

## 호환성

기존 JS 및 Arduino의 암호 계산과 패킷 형식은 유지합니다. `set_key`와 `copy_key`는 인증 플래그를 자동 변경하지 않습니다. 인증 승인·재접속·키 변경에 따른 상태 관리, challenge 만료와 메시지 재전송 검사는 호출 측 책임입니다.

`ENC_PACK`과 `ENC_488`은 선언 길이와 실제 길이가 일치해야 합니다. `ENC_E2E`는 선언 길이의 라우팅 헤더 뒤에 독립 E2E 본문을 포함할 수 있습니다. 자세한 구조는 [프로토콜과 사용 범위](PROTOCOL.md)를 참고하세요.

## 검증 범위

`npm test`는 빌드, 소스·ESM·UMD 회귀 테스트, TypeScript 검사를 수행합니다. 선택적 `test:arduino`와 `test:iosignal`은 관련 저장소를 사용해 호스트에서 상호운용성을 검사합니다.

호스트 테스트는 물리 Arduino 보드의 SRAM·stack 사용량이나 실제 네트워크 동작을 보증하지 않습니다.
